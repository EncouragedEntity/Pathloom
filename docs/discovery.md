## Дослідження

- **tldraw** — source-available, не open source. Для продакшну потрібен ліцензійний ключ, комерційна ліцензія платна (ціна через sales). Несумісний з D11. **Відкинуто.**
- **Excalidraw** — MIT, але власні типи елементів і toolbar кастомізуються погано. Як база для smart-об'єктів слабкий.
- **Tauri 2 vs Electron** — Tauri значно менший за розміром і пам'яттю. Ризик: на Linux WebKitGTK відстає (частина API, наприклад OffscreenCanvas, нестабільна). Перевірити бенчмарком на ранньому етапі.
- **Референс** — відео «Я попытался сделать ВИРУСНУЮ ROBLOX игру с помощью ИИ» (Whistle Lab). Дошку на скріншотах автор використовує для roadmap гри, яку будує Claude Opus. Субтитри отримати не вдалося.

## Технічний напрям

**D16 (переглянуто). Rust-ядро + веб-UI у Tauri 2.** Власник погодився з рекомендацією («якщо ти впевнений»). C++ не розглядаємо. Попередній варіант «увесь UI на Rust» лишається запасним, якщо spike Tauri на Linux провалиться.

Причини: UI на React пишеться і змінюється значно швидше; HTML-прототипи Stage 4 переходять у продакшн; для полотна з тисячами об'єктів швидкодія визначається архітектурою рендеру, а не мовою.

**D17. Агент працює без відкритого застосунку.** Один Rust-крейт `pathloom-core` (модель, формат файлів, граф залежностей, валідація) використовують три клієнти:
- `pathloom` CLI (`board create`, `task add`, `task done`, `next`, `apply <spec>`, `validate`);
- `pathloom mcp` — MCP-сервер (stdio) з тими самими операціями;
- десктоп-застосунок.
Агент може також правити файли `plan/` напряму. Відкритий застосунок стежить за файлами (file watcher) і одразу перемальовує зміни, підсвічуючи зроблене агентом. Запис файлів атомарний; конфлікт із незбереженою правкою в UI показується користувачу.

---

Попередній текст D16 (для історії):

**D16. Увесь застосунок на Rust** (рішення власника). Без webview, без TypeScript. C++ не розглядаємо.

Код пише й підтримує Claude. Власник Rust не знає, трохи знає C++. Тому репо має бути самодостатнім для нової сесії без пам'яті: `CLAUDE.md`, ADR у `docs/adr/`, тести на критичну логіку.

Кандидати на UI (вибір — після spike):
- **GPUI + gpui-component** — GPU-рендер (рушій Zed), готові віджети: dock, теми, Markdown, текстовий редактор. Ризики: API змінюється, crates.io-реліз відстає від Zed main, Windows найменш протестований.
- **egui + wgpu** — зрілий, простий, стабільний. Ризик: складно зробити гарний «продуктовий» вигляд.
- Полотно в будь-якому варіанті: власний рендер (GPU-шляхи; кандидат `vello`), sketch-стиль — порт алгоритмів rough.js, layout графа — Rust-крейт або власний layered layout.

**Spike перед вибором (1–2 дні):** у кожному кандидаті — pan/zoom 2000 об'єктів, редагування тексту українською, картка задачі за макетом, вимір пам'яті й FPS на Windows і Linux.

Втрати від відмови від вебу: менше готових бібліотек (rich text, PDF-перегляд, accessibility), більше власного коду. Виграш: одна бінарка, менше пам'яті, однаковий рендер на всіх ОС, немає ризику WebKitGTK.

## Відкриті питання

- Остаточний вибір canvas-підходу (власний vs форк Excalidraw) — після прототипу.
- Формат `*.board.json` і merge-стратегія для конфліктів позицій.
- Підпис інсталяторів (Apple Developer, Windows code signing) — потрібні сертифікати, інакше система показуватиме попередження.
