## Дослідження

- **tldraw** — source-available, не open source. Для продакшну потрібен ліцензійний ключ, комерційна ліцензія платна (ціна через sales). Несумісний з D11. **Відкинуто.**
- **Excalidraw** — MIT, але власні типи елементів і toolbar кастомізуються погано. Як база для smart-об'єктів слабкий.
- **Tauri 2 vs Electron** — Tauri значно менший за розміром і пам'яттю. Ризик: на Linux WebKitGTK відстає (частина API, наприклад OffscreenCanvas, нестабільна). Перевірити бенчмарком на ранньому етапі.
- **Референс** — відео «Я попытался сделать ВИРУСНУЮ ROBLOX игру с помощью ИИ» (Whistle Lab). Дошку на скріншотах автор використовує для roadmap гри, яку будує Claude Opus. Субтитри отримати не вдалося.

## Технічний напрям

**D16 (переглянуто). Rust-ядро + веб-UI у Tauri 2.** Власник погодився з рекомендацією («якщо ти впевнений»). C++ не розглядаємо. Попередній варіант «увесь UI на Rust» лишається запасним, якщо spike Tauri на Linux провалиться.

Причини: UI на React пишеться і змінюється значно швидше; HTML-прототипи Stage 4 переходять у продакшн; для полотна з тисячами об'єктів швидкодія визначається архітектурою рендеру, а не мовою.

**D17. Агент працює без відкритого застосунку.** Один Rust-крейт `pathloom-core` (модель, формат файлів, граф залежностей, валідація) використовують три клієнти:
- `pathloom` CLI (`board create`, `task add`, `task done`, `next`, `apply <spec>`, `validate`);
- `pathloom mcp` — MCP-сервер (stdio) з тими самими операціями;
- десктоп-застосунок.
Агент може також правити файли `plan/` напряму. Відкритий застосунок стежить за файлами (file watcher) і одразу перемальовує зміни, підсвічуючи зроблене агентом. Запис файлів атомарний; конфлікт із незбереженою правкою в UI показується користувачу.

---

Попередній текст D16 (для історії):

**D16. Увесь застосунок на Rust** (рішення власника). Без webview, без TypeScript. C++ не розглядаємо.

Код пише й підтримує Claude. Власник Rust не знає, трохи знає C++. Тому репо має бути самодостатнім для нової сесії без пам'яті: `CLAUDE.md`, ADR у `docs/adr/`, тести на критичну логіку.

Кандидати на UI (вибір — після spike):
- **GPUI + gpui-component** — GPU-рендер (рушій Zed), готові віджети: dock, теми, Markdown, текстовий редактор. Ризики: API змінюється, crates.io-реліз відстає від Zed main, Windows найменш протестований.
- **egui + wgpu** — зрілий, простий, стабільний. Ризик: складно зробити гарний «продуктовий» вигляд.
- Полотно в будь-якому варіанті: власний рендер (GPU-шляхи; кандидат `vello`), sketch-стиль — порт алгоритмів rough.js, layout графа — Rust-крейт або власний layered layout.

**Spike перед вибором (1–2 дні):** у кожному кандидаті — pan/zoom 2000 об'єктів, редагування тексту українською, картка задачі за макетом, вимір пам'яті й FPS на Windows і Linux.

Втрати від відмови від вебу: менше готових бібліотек (rich text, PDF-перегляд, accessibility), більше власного коду. Виграш: одна бінарка, менше пам'яті, однаковий рендер на всіх ОС, немає ризику WebKitGTK.

**D30. Докази й контроль агентів (2026-11-05).** Зроблено ідеї №33–36, 38, 39. Ключові рішення:
- Доказ — частина файлу етапу (git-видимий), а не машинний стан. Невдала перевірка ніколи не закриває задачу.
- `require_evidence` обмежує лише агентів через MCP: людина в застосунку вирішує сама.
- MCP-сервер не виконує команди з файлів плану (гейти, `--run`): агент запускає їх сам і звітує. Виконують лише CLI (явна команда користувача) і застосунок (після підтвердження команди).
- Heartbeat — у `claims.json`, не в журналі: інакше журнал заповнять пінги.
- Витрати лише відображаються з того, що повідомив клієнт.
Деталі — `docs/m8-proof-contracts.md`.

**D31. Оновлення без розриву агентів (2026-11-05).** `pathloom.exe` у папці застосунку працює як MCP-сервер, поки жива сесія AI-клієнта, і Windows не дає його перезаписати. NSIS-хук (`apps/desktop/src-tauri/windows/hooks.nsh`) перед встановленням перейменовує зайнятий файл у `pathloom.N.old` (запущений exe перейменувати можна) і кладе новий. Старі сесії доживають на старій копії, нові беруть нову; `.old` видаляє наступне встановлення, а після видалення програми — перезавантаження. Процеси агентів не вбиваємо. MSI цього хука не має, тому для оновлень рекомендуємо `.exe`. Відкритий сам застосунок інсталятор, як і раніше, просить закрити (у тихому режимі `/S` закриває сам).

**D32. Зрозумілі плани (2026-11-05).** Плани, складені агентами (Maestro: 37 етапів, 82 стрілки), були нечитабельні: картки накладались після росту, нові ставились будь-де, стрілки тягнулись через усю дошку. Рішення:
- Повна розкладка (`layout_full`): кожна рамка (фаза) — окремий блок колонок, порядок блоків за залежностями між фазами; вкладена рамка йде в блок батьківської; всередині — шари за найдовшим шляхом, порядок у колонці — барицентр сусідів (8 проходів), y — на рівні попередників. На Maestro: 0 накладань, перетинів 223 → 127.
- `autoLayout` на дошці: після кожного `apply` агента дошка перебудовується в ядрі (працює й без відкритого застосунку). Картка, яку людина перетягнула, отримує `pinned: true` і не рухається.
- Стрілки: зайві (A→C при A→B→C) сховані; стрілки між двома рамками (2+) — одна товста з числом; наведення/вибір картки підсвічує її ланцюг, решта притухає; виконані попередники бліді.
- Картка, що виросла, зсуває нижні вниз і розширює рамку (у полотні).
- Правила для агентів у skill + `validate.hints` (`REDUNDANT_DEP`, `BIG_STAGE`, `NO_DESCRIPTION`), `description` в `apply`. Рамки — фази за часом, а не кошики статусів.

**D33. Ліцензії та документація для розробників (2026-11-05).** Перевірено всі залежності, що потрапляють у збірку: 510 Rust-крейтів (усі платформи) і 55 npm-пакетів. Усі дозвільні; винятки з умовами: MPL-2.0 (`cssparser`, `selectors`, `dtoa-short`, `option-ext` — через Tauri, використовуються без змін) і OFL-1.1 (шрифти Inter, JetBrains Mono, Caveat — текст ліцензії тепер постачається з застосунком). Список дозволених ліцензій — у CONTRIBUTING.md; `npm run licenses` перевіряє їх і генерує THIRD-PARTY-LICENSES.md (також у CI та в інсталяторі, відкривається з Налаштувань). Додано CONTRIBUTING.md, SECURITY.md, docs/architecture.md, docs/README.md.

## Відкриті питання

- Остаточний вибір canvas-підходу (власний vs форк Excalidraw) — після прототипу.
- Формат `*.board.json` і merge-стратегія для конфліктів позицій.
- Підпис інсталяторів (Apple Developer, Windows code signing) — потрібні сертифікати, інакше система показуватиме попередження.
