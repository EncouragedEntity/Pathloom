# Pathloom — ідеї та рекомендації

Список того, що варто додати, змінити або покращити після MVP. Відсортовано за моєю оцінкою «користь / складність». Позначки: 🟢 мало роботи, 🟡 середньо, 🔴 багато.

## 1. Найбільша цінність для роботи з агентами

1. ✅ **Захоплення задач агентом (claim).** 🟡 — зроблено (2026-11-05).
   Агент перед роботою «бере» задачу: `claim_task(AUTH-02)`. На картці з'являється «працює Claude», і другий агент цю задачу не візьме. Захоплення знімається, коли задачу закрито або минув тайм-аут.
   Це головне, що потрібно, коли паралельно працюють кілька агентів (Claude Code, Codex, Cursor), бо інакше двоє беруться за одне й те саме.
2. ✅ **Виконавець з ім'ям агента.** 🟢 — зроблено, плюс профілі агентів (ім'я, колір, аватар).
   Розширити `who` до `ai:claude`, `ai:codex`, `me`, `friend:Оля`, щоб у кожного агента був свій колір на картці та фільтр «що робить Claude».
3. ✅ **Журнал дій агентів.** 🟢 — зроблено (без відкату окремої дії).
   `.pathloom/log/agent.jsonl` (є в специфікації, але ще не пишеться) плюс стрічка «хто що змінив» в «Огляді».
   Дозволить переглянути, що агент робив уночі, і відкотити окрему дію.
4. **Git-зв'язка.** 🟡
   - `pathloom hook install` ставить git-хук: коміт із `AUTH-02` у повідомленні позначає задачу або додає коментар із хешем коміту.
   - Поле `branch` показує, чи гілку вже злито в `main`, і пропонує закрити етап.
5. **Критерії готовності (acceptance criteria).** 🟢
   Окремий блок у файлі етапу. Агент читає його через `get_stage` і сам перевіряє, чи задача справді готова, а не просто «написав код».
6. ✅ **Події для агентів.** 🟡 — зроблено як `pathloom watch --json`.
   MCP-ресурс із підпискою (або `pathloom watch --json`), щоб агент дізнавався, що людина змінила план, без постійного опитування.
7. **Мульти-агентний режим із ролями.** 🔴
   Профілі агентів («архітектор», «виконавець», «рев'юер») з дозволами в `project.toml`. Наприклад, рев'юер може лише коментувати, а виконавець — лише відмічати задачі.

> Для твого проєкту з агентами Pathloom може стати **спільною пам'яттю та планом** для кількох агентів. Пункти 1, 3 і 6 — якраз той мінімальний «протокол координації», який для цього потрібен: хто що бере, що вже зроблено, що змінилося.

16. **Мінімапа не повинна перекривати картки:** автоматично ховати її, коли під нею щось є, або зробити напівпрозорою. 🟢

19. **Кращий auto-layout:** кілька проходів barycenter і центрування батьків над дітьми. Зараз один прохід. 🟡
20. **Git merge driver для `*.board.json`** — якщо в команді почнуться конфлікти позицій. 🟡
21. **Обмеження з §9 специфікації** (розміри spec, кількість елементів) для захисту від дуже великих запитів агентів. 🟢
22. **`pathloom import`** з Mermaid / Markdown-списків / JSON Canvas (Obsidian) / `.excalidraw`. 🟡
23. **MCP через localhost HTTP,** щоб один застосунок обслуговував кількох агентів і віддалені середовища. 🟡

## 6. Ідеї з брифу Maestro (загальні для будь-якого клієнта)

Pathloom і Maestro — окремі продукти. Нижче лише те, що корисне будь-якому агенту чи оркестратору.

33. **«Готово» з доказом.** 🟡
    Задача може мати `evidence`: команда, exit code, тривалість, посилання на лог. Картка показує «✓ перевірено» лише тоді, коли доказ є.
    Це закриває біль «агент сказав готово, але нічого не запускав». MCP: `set_task {done, evidence}`. У налаштуваннях проєкту можна вимагати доказ для етапів з `kind: stage`.
34. **Heartbeat замість тихого зависання.** 🟢
    Claim уже має TTL. Додати `last_heartbeat` і стан «агент мовчить N хв»: на картці жовтий індикатор, в «Огляді» — «можливо, завис».
35. **Артефакти етапу.** 🟢
    Поле `artifacts: [specs/auth/spec.md, plan.md]` — посилання на файли-хендофи (spec, plan, review). Інспектор відкриває їх, а агент отримує через `get_stage`.
    Правило «хендоф = артефакт, а не переказ» тоді видно прямо на дошці.
36. **Імпорт Spec Kit / Kiro / BMAD.** 🟡
    `pathloom import spec-kit specs/<feature>/tasks.md` перетворює задачі на етапи й залежності. Великий наявний потік користувачів.
37. ✅ **Skill у відкритому форматі Agent Skills.** 🟢 — `pathloom skill install` / `init --agents-skill`.
    Окрім плагіна Claude Code, класти `.agents/skills/pathloom/SKILL.md` (`pathloom init --agents-skill`). Цей каталог читають Codex, Gemini CLI, Cursor, Copilot, Zed, Goose, OpenCode.
38. **Облік використання (необов'язковий).** 🟡
    Клієнт може додати до запису журналу `usage {tokens_in, tokens_out, cost}`. «Огляд» показує вартість за етапом і агентом.
    Сам Pathloom нічого не рахує й ключів не торкається — лише відображає те, що повідомив клієнт.
39. **Перевірка коду (gates) як етап.** 🟡
    Етап `kind: gate` з командою (`npm test`). Агент виконує її й прикріплює доказ; етап стає «готово» лише з exit code 0.
