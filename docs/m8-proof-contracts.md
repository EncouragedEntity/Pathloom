# Докази, heartbeat, артефакти, гейти, витрати, імпорт — контракти

Ідеї №33–36, 38, 39 з `docs/ideas.md`. Протокол лишається `pathloom/1`; нові можливості в `capabilities`:
`evidence`, `heartbeat`, `import`, `artifacts`, `usage`, `gates` (у `--read-only` сервера їх немає, крім `artifacts`).

## 1. Доказ виконання (`evidence`)

Frontmatter етапу, ключ — id задачі (або ключ етапу для гейта):

```yaml
evidence: {AUTH-02: {command: cargo test, exit_code: 0, duration_ms: 5120, summary: 94 passed, at: 2026-11-05T09:02:48Z, by: claude}}
```

- Поля: `command` (1–500 символів), `exit_code`, `duration_ms?`, `summary?` (≤120), `log?` (посилання або шлях без пробілів, не `javascript:`/`data:`), `at`, `by` (заповнює Pathloom).
- Зберігається лише для задач, які є і виконані: зняття галочки або видалення задачі прибирає доказ під час запису.
- `exit_code ≠ 0` не закриває задачу (`INVALID_SPEC` у MCP, `CHECK_FAILED` у CLI).
- MCP: `set_task {task_id, done: true, evidence}`. CLI: `pathloom task done ID --run "cmd" [--summary] [--log]` — CLI сам запускає команду через системну оболонку.
- `.pathloom/project.toml`: `require_evidence = true` — MCP відмовляє закривати задачі етапів `kind: stage` без доказу (`EVIDENCE_REQUIRED`), так само для `tasks_done` в `apply`. Клацання людини в застосунку й CLI без `--run` не обмежені.
- Застосунок: друге кільце навколо галочки на картці; щит «Перевірено» з підказкою в інспекторі; перемикач у Налаштування → AI-агенти.
- Невалідний `evidence`, відредагований руками, не ламає етап: зберігається як є й ігнорується.

## 2. Heartbeat

- `claims.json`: у захопленні нове поле `heartbeat_at` (старі файли без нього — рахується `at`).
- MCP `heartbeat {task_id?, note?}`, CLI `pathloom task heartbeat [ID] [--note]`: оновлює `heartbeat_at`, подовжує захоплення щонайменше на 30 хв, замінює нотатку. Не пишеться в журнал.
- Будь-яка дія агента, що пишеться в журнал (CLI/MCP), теж оновлює `heartbeat_at` його захоплень (без подовження).
- «Мовчить»: без ознак життя 10 хв (`SILENT_AFTER_SECS`). `ClaimView` має `heartbeatAt`, `silent`, `note`; `pathloom claims` показує `[silent since …]`.
- Застосунок: чип захоплення жовтий і пунктирний, крапка на картці жовта, в «Огляді» позначка «мовчить». Поки є захоплення, застосунок перечитує їх щохвилини.

## 3. Артефакти

- Frontmatter `artifacts: [specs/auth/spec.md, "https://…"]`. Шлях відносно кореня проєкту (без `..`, `:` і початкового `/`) або http(s)-посилання; до 30 на етап.
- `apply`: `stages[].artifacts_add` (дедуплікація). `get_stage` повертає `artifacts`.
- Застосунок відкриває файл системною програмою лише якщо він існує всередині проєкту (canonicalize + starts_with); посилання — після підтвердження.

## 4. Гейти

- `kind: gate` + `check: npm test`. Результат — `evidence[<ключ етапу>]`.
- Гейт виконано, коли перевірка пройшла і всі задачі (якщо є) виконані. Прогрес рахує перевірку як ще один пункт.
- Невдалий запуск прибирає попередній успішний результат (гейт знову відкритий).
- MCP `set_gate {key, evidence}` — агент сам запускає команду й звітує (MCP-сервер команди з файлів не виконує). CLI `pathloom gate run KEY` виконує `check`. Застосунок: кнопка «Запустити перевірку» з підтвердженням команди.

## 5. Витрати (`usage`)

- Запис журналу може мати `usage {tokens_in, tokens_out, cost_usd?}`. MCP `report_usage {…, stage?, note?}`, CLI `pathloom usage --tokens-in N --tokens-out N [--cost X] [--stage K]`.
- `pathloom usage` / застосунок («Огляд» → «Витрати») сумують увесь журнал по агентах і етапах; запис на кілька етапів ділиться порівну.
- Pathloom нічого не рахує сам і ключів не торкається.

## 6. Імпорт Spec Kit

- `pathloom import spec-kit FILE [--prefix ABC] [--board B] [--dry-run] [--direct]`, MCP `import_tasks {format: "spec-kit", text, prefix?, board?, dry_run?}`.
- Кожна секція `##` із чекбоксами — етап (задачі з `###` усередині теж); блоки коду пропускаються. Без секцій — один етап із назвою з `# Tasks: …`.
- Ключі `<префікс><номер фази>`; префікс — ініціали назви фічі або `--prefix` (1–5 літер). Етап із таким ключем, але іншою назвою — помилка.
- Залежності: фаза чекає попередню; фази «User Story» чекають останню не-story фазу (паралельні); фаза після історій чекає їх усіх. Задаються лише для нових етапів.
- Повторний імпорт: нові задачі додаються, відмічені в файлі позначаються виконаними, нічого не видаляється. Усі етапи — у рамці з назвою фічі. Режим review поважається.
